# npm workspace change impact

`blueprint-ai impact PROJECT --base-ref REF --json` reads Git changes and the root npm `workspaces` declaration. It maps each changed file to the deepest declared package, then includes packages that declare a dependency on a changed package, directly or transitively. A parent package containing a nested workspace is included even without a declared dependency. Root package and lockfiles, `.npmrc`, workspace configuration, root scripts and workflow changes conservatively select every package. Unmapped paths also select every package but retain `partial` status and their exact filenames so a maintainer can review the unknown edge. No project code or test script runs.

The default comparison ref is `HEAD`, which includes current worktree changes. Supply a reviewed base ref to compare a longer branch range. The result lists each selected package's declared test script and tracked candidate test files. These are suggestions for a maintainer to inspect and run, not proof of coverage or a safe reason to skip other checks. Package-level selection does not understand task inputs, dynamic imports, generated code, Python workspaces, CI policy outside the listed global paths, or changes in an unavailable package manifest.

This deliberately adopts the package-graph idea described by [Nx affected projects](https://nx.dev/docs/reference/nx-commands#nx-affected) and [Turborepo affected packages](https://turborepo.dev/docs/reference/run#--affected). Blueprint does not copy their source, run either product, use their caches, or claim their finer task-input analysis. The implementation uses Blueprint's existing bounded Git inventory and Python standard library.
