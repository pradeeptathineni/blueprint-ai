# Phase 1 tool research

Snapshot: 2026-09-11. Primary sources are the linked upstream repositories and documentation. Adoption figures are approximate GitHub stars observed on the snapshot date; they are signals, not selection criteria by themselves. Every default runs locally and in CI, supports macOS/Linux/Windows directly or through standard runtimes, and remains optional.

## Decisions

| Capability | Default routing | Alternates considered | Decision evidence |
|---|---|---|---|
| Tool discovery/meta-lint | Native manifest discovery, then narrow adapters | [Super-Linter](https://github.com/super-linter/super-linter), [MegaLinter](https://github.com/oxsecurity/megalinter), [static-analysis catalog](https://github.com/analysis-tools-dev/static-analysis) | Meta-linters offer breadth but add container/runtime weight, overlapping output, and coarse applicability. Keep them as catalog/CI alternatives rather than V1 engine dependencies. |
| Python quality | [Ruff](https://github.com/astral-sh/ruff) (~49.6k, MIT) | native compiler, pylint, flake8 | Actively maintained, fast single binary, low install friction, configurable and machine-readable JSON/SARIF. Native `compileall` remains semantic authority when compilation is requested. |
| JS/TS quality | [Biome](https://github.com/biomejs/biome) (~25.8k, Apache-2.0), then [ESLint](https://github.com/eslint/eslint) (~27.5k, MIT) when project-configured | TypeScript compiler | Biome is fast and integrated; ESLint has broader plugin adoption. Project-native `tsc` is authoritative for type validity. Routing avoids duplicate formatter findings. |
| Shell/duplication/size | [ShellCheck](https://github.com/koalaman/shellcheck) (~40k, GPL-3.0), [jscpd](https://github.com/kucherenko/jscpd) (~6.2k, MIT), [scc](https://github.com/boyter/scc) (~8.7k, MIT) | custom heuristics | Mature, configurable CLI output and low friction. Phase 1 exposes ShellCheck routing; jscpd/scc are deferred until normalized duplication/complexity evidence adds value beyond noise. No third-party code is copied. |
| SAST | [Semgrep](https://github.com/semgrep/semgrep) (~16.6k, LGPL-2.1) | native linters, Trivy | Strong language breadth and JSON/SARIF, but ruleset downloads, install size, and false-positive tuning raise friction. Kept as an alternate until explicit local rules exist. |
| Secrets | [Gitleaks](https://github.com/gitleaks/gitleaks) (~29.2k, MIT) | TruffleHog, Trivy | Fast single binary, local/CI friendly, configurable JSON/SARIF. Trivy supplies an overlapping fallback; Blueprint AI only checks sensitive filenames itself. |
| Dependencies/repository security | [OSV-Scanner](https://github.com/google/osv-scanner) (~11k, Apache-2.0) plus [Trivy](https://github.com/aquasecurity/trivy) (~37.9k, Apache-2.0) | Grype, OSSF Scorecard | Both are actively maintained, cross-platform, structured, and broadly adopted. OSV-Scanner is the focused dependency default; Trivy adds repository/misconfiguration coverage. Findings are deduplicated. Scorecard is better suited to public supply-chain posture than arbitrary folders. |
| Tests | Native pytest/package scripts and declared frameworks | Playwright, Hypothesis, Schemathesis, k6 | Native runners are semantic authority and preserve project configuration. Specialized tools remain applicability-driven later layers; running them universally would add false negatives and install cost. |
| Terraform | [Terraform CLI](https://github.com/hashicorp/terraform) validation, then [TFLint](https://github.com/terraform-linters/tflint) (~5.8k, MPL-2.0) and [Checkov](https://github.com/bridgecrewio/checkov) (~9k, Apache-2.0) | Trivy misconfiguration | `terraform validate -json` is authoritative and fast; TFLint adds provider rules; Checkov adds policy breadth with higher install/false-positive cost. |
| CloudFormation | [cfn-lint](https://github.com/aws-cloudformation/cfn-lint) (~2.6k, MIT-0) | [CloudFormation Guard](https://github.com/aws-cloudformation/cloudformation-guard) (~1.4k, Apache-2.0), Checkov | cfn-lint provides native-schema correctness and JSON; Guard is valuable when a project supplies policy rules, so it is not invoked without them. |
| GitHub Actions | [actionlint](https://github.com/rhysd/actionlint) (~4.2k, MIT) plus [zizmor](https://github.com/zizmorcore/zizmor) (~6.5k, MIT) | Super-Linter | Both are fast binaries with configurable structured output. actionlint targets syntax/semantics with a low false-positive goal; zizmor adds security/SARIF. A simple SHA-pin rule remains deterministic even when tools are absent. |
| Repository hooks | [pre-commit](https://github.com/pre-commit/pre-commit) (~15.6k, MIT) | language-specific hooks | Cross-language, local/CI capable, configurable, established. The generated baseline pins [pre-commit-hooks v6.0.0](https://github.com/pre-commit/pre-commit-hooks/releases) and remains deliberately small. |
| Dependency updates | [Renovate](https://github.com/renovatebot/renovate), Dependabot | manual updates | Both are mature. They mutate hosting state and are outside local V1 review/apply; recommend rather than invoke. |
| Architecture boundaries | [Import Linter](https://github.com/seddonym/import-linter) (~1.2k, BSD-2-Clause), [dependency-cruiser](https://github.com/sverweij/dependency-cruiser) (~7.2k, MIT), [ArchUnit](https://github.com/TNG/ArchUnit) (~3.8k, Apache-2.0) | model-only review | Strong ecosystem-specific choices, but each requires project-authored boundary policy for a good false-positive profile. Phase 1 reserves the adapter/model boundary rather than inventing constraints. |
| Documentation | [markdownlint-cli2](https://github.com/DavidAnson/markdownlint-cli2) (~0.9k, MIT) and [lychee](https://github.com/lycheeverse/lychee) (~3.9k, Apache-2.0) | Vale | Both are maintained, configurable, local/CI friendly, and structured enough to normalize. Vale is preferable when a project supplies prose style policy; it is not a default correctness check. Network link checks are inherently slower and less stable, so tool failures stay partial. |
| Model context | Minimal native selector; [Repomix](https://github.com/yamadashy/repomix) (~28.3k, MIT) alternate | [Aider repo map](https://github.com/Aider-AI/aider) (~48.9k, Apache-2.0), [Tree-sitter](https://github.com/tree-sitter/tree-sitter) | Repomix has excellent ignore, token, compression, and security features, but Node installation is disproportionate for the Python V1. The native selector caps bytes, ranks blueprint files, reduces large code to signatures, and redacts secrets; an adapter can replace it later. Remote packing is deliberately excluded from the trust model. |
| Model provider | Optional [OpenAI Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create) using `gpt-5-mini` | provider protocol and fakes | Responses supports bounded output, Structured Outputs, and non-stored requests. `gpt-5-mini` supports Structured Outputs and remains a cost-sensitive default; an environment override can select another model. No SDK or credential is required for deterministic operation. |
| Finding interchange | Internal Pydantic schema | SARIF, [reviewdog](https://github.com/reviewdog/reviewdog) (~9.6k, MIT) | The internal record preserves Blueprint-specific priority, remediation, provenance, and evidence. Adapters consume structured formats now; SARIF emission/reviewdog transport remains a later edge concern. |

## Operational policy

Availability and version checks never fail a run. Commands are fixed in typed adapters, run without a shell, receive bounded timeouts, and parse structured output where available. Missing tools yield actionable status; nonstandard exits or parse failures become partial results. Network-requiring tools are never auto-installed. License compatibility matters for redistribution, but Blueprint AI executes CLIs and copies none of their code.
